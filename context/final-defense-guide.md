## I. PowerPoint Presentation

Prepare a concise presentation that explains the project, presents the research findings, and summarizes the conclusions and recommendations.

### Part A. Brief Overview of the Project

1. Project title, names of group members, capstone adviser, and FIC name.
2. Purpose of the system: explain what the system is intended to accomplish.
3. Problem or need addressed by the system: present the key findings from the needs assessment (NA), when applicable.
4. Intended users or beneficiaries of the system.
5. Brief overview of the system's major functions.
6. Types of users or user roles in the system.
7. Responsibilities and access levels of each user role.
8. Features available to each role, preferably summarized in a clear list or table.

### Part B. Research Results and Recommendations

9. Present the research problems in one slide.
10. Present the key findings for each research problem. Focus on the highlights rather than copying large tables directly from the manuscript. If appropriate, use one slide for each research problem.
11. Present the summary of findings in one slide.
12. Present the conclusions in one slide.
13. Present the recommendations in one slide.
14. Keep supporting evidence of data collection and its documentation available in the presentation or backup files in case the panel asks to see it.

## II. Recorded System Demonstration / Walkthrough

Demonstrate the actual working system in a logical sequence. Include only the steps and features that apply to your project. Use test or demonstration accounts where appropriate, and make sure the data shown is ready before recording.

### A. Administrator Flow (if applicable)

15. Log in using the administrator's assigned demonstration credentials.
16. Show the dashboard and briefly explain the important information displayed.
17. Demonstrate how the administrator manages user accounts and system records, if these functions are available.
18. Show how the administrator reviews and processes submitted transactions or requests, if applicable.
19. Demonstrate how the status of records or transactions is updated.
20. Show how reports are generated or viewed, if available.
21. Show notifications or monitoring features, if applicable.
22. Log out of the system.

### B. End-User Flow (if applicable)

23. Register an account or log in using an end-user demonstration account.
24. Show the dashboard and available user features.
25. Enter the required information and submit a transaction, form, or request.
26. Show the system's validation and feedback after submission.
27. Demonstrate how the user checks or monitors the status of the submitted transaction or request.
28. Show notifications or updates received by the user, if applicable.
29. Show how the user views or downloads the resulting document, report, or other output, if available.
30. Log out of the system.

## III. Video and Presentation Requirements

- **Prepare a walkthrough script.** Plan the narration beforehand and rehearse it. Keep the explanation concise and focused on the system's purpose and key functions.
- **Follow a clear sequence.** Present the administrator flow first, followed by the end-user flow, when both roles are part of the system.
- **Use background music sparingly.** Light background music may be used during the opening or transitions. Keep it subtle and make sure it never competes with the narration.
- **Check the audio.** Ensure that the voice-over is clear and audible throughout the video. Review the final edited version before submission.
- **Observe presentation appearance.** Wear decent, appropriate attire. Add a caption identifying each presenter beneath their name on the slides. Use one consistent Zoom background template throughout. Voice-over is acceptable for the system walkthrough.
- **Observe the time limit.** The system demonstration video must not exceed 10-15 minutes.
